Troubleshooting

Common issues encountered while configuring, running, or contributing to the LG Vehicles Report Workflow, and how to resolve them. If your issue isn't listed here, open an issue on GitHub.

Configuration & Connections

No data / everything skipped

This workflow only reads from the EarthRanger subject group Vehicles — this name is hardcoded in spec.yaml and is not a configurable field anywhere in the workflow form. If your instance's vehicles are registered under a different subject group name, this workflow won't find them.

EarthRanger connection fails or times out

Verify the server URL, username, and password configured in the Data Source Connection. Confirm you can log into that same EarthRanger instance directly in a browser with the same credentials. Credentials aren't validated at setup time, so an invalid password only surfaces once the workflow actually runs.

Study area layers (Conservancies / Group Ranch Boundaries) are missing from the maps

These layers are not downloaded from Dropbox — they're fetched live from your connected EarthRanger instance as spatial features of type Conservancies and Group Ranch Boundaries. If your EarthRanger instance doesn't have spatial features registered under those exact names, both layers will simply be absent from every map, with no separate error.

Basemap tiles don't load, or the background map is blank

The Basemap Layers URLs are user-editable. If you changed either the ESRI World Hillshade or World Street Map layer away from its default, confirm the new tile URL follows the standard {z}/{y}/{x} template and is reachable from the machine running the workflow.

Trajectories & Map Outputs

Speed Map or Vehicle Tracks map is empty or sparse for a vehicle

This is usually the Trajectory Filter discarding most of the vehicle's data. Vehicles can travel much faster than wildlife, so if a vehicle's typical speed falls outside the default 3–150 km/h bounds, or its fix intervals fall outside the 1 s–6 h duration bounds, loosen the thresholds to match, then re-run.

Map is zoomed too tight or too loose around the tracks

Adjust the Zoom to Envelope Expansion Factor — 1.0 is a tight fit to the data extent; increase it (e.g. 1.2) to add padding around the map. Both the Speed Map and Vehicle Tracks map share the same computed view state.

Speed Over Time chart is missing a vehicle, or shows a flat/empty line

Each vehicle gets its own chart, generated only from that vehicle's own trajectory segments. A vehicle with very few fixes in the analysis window (or whose segments were all discarded by the Trajectory Filter) will produce a sparse or empty chart rather than an error.

No outputs written / can't find results

All outputs are written to the directory specified by the ECOSCOPE_WORKFLOWS_RESULTS environment variable. Confirm it's set and points to a directory the workflow process can write to.

Contributing & CI

These apply if you're modifying the workflow itself (spec.yaml, test-cases.yaml, or the generated ecoscope-workflows-vehicles-report-workflow/ directory) and opening a pull request.

Generated files differ from committed files in ecoscope-workflows-vehicles-report-workflow

The generated workflow directory is out of sync with spec.yaml. Run the recompile script locally and commit the result:

pixi run --manifest-path pixi.toml --locked bash -c "./dev/recompile.sh --update"

Found wildcard version (*) in requirements or Found local file channel (file://) in requirements

In spec.yaml, every dependency under requirements must pin an exact version and use a remote conda channel — wildcard versions and local file:// channels are only valid for local development, not for CI using published packages.

VERSION.yaml (...) must be greater than main branch (...)

Bump MAJ/MIN/PATCH in ecoscope-workflows-vehicles-report-workflow/VERSION.yaml so it's strictly greater than the version on main before opening or updating a PR.

test-cases.yaml must contain at least one test case

Every workflow requires at least one top-level entry in test-cases.yaml with a params block. See the existing entries in that file for the expected format.

Workflow tests fail in CI but pass locally (or vice versa)

test.yml runs test cases against all of ubuntu-latest, macos-latest, and windows-latest. If a test only fails on CI, check whether it depends on EarthRanger credentials being available as secrets, on the Conservancies/Group Ranch Boundaries spatial features existing on the test EarthRanger instance, or on OS-specific path handling.
